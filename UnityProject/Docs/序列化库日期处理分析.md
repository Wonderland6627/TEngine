# 序列化库日期处理分析

## 问题根源

**核心问题**：不同序列化库对 Date/DateTime 的处理方式不同

### 1. JavaScript 端（云函数）
- **默认行为**：`JSON.stringify(new Date())` 会序列化为 ISO 8601 字符串
- **但**：微信云数据库返回的 Date 对象可能已经是特殊格式
- **问题**：直接返回 Date 对象，序列化格式不确定

### 2. C# 客户端端（Newtonsoft.Json）
- **默认行为**：期望 ISO 8601 格式字符串（如 `"2025-05-06T13:18:42.514Z"`）
- **问题**：如果收到时间戳或其他格式，会解析失败

---

## 不同序列化库的日期处理

### Newtonsoft.Json (Json.NET) - 当前使用
```csharp
// 默认：期望 ISO 8601 字符串
// 可以配置：支持多种格式
var settings = new JsonSerializerSettings
{
    DateFormatString = "yyyy-MM-ddTHH:mm:ss.fffZ",
    // 或使用 IsoDateTimeConverter
    Converters = { new IsoDateTimeConverter() }
}
```

### System.Text.Json (.NET Core)
```csharp
// 默认：ISO 8601 格式
// 配置更灵活
var options = new JsonSerializerOptions
{
    PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
    // 日期格式配置
}
```

### Unity JsonUtility
```csharp
// 限制：只支持 ISO 8601 格式
// 不支持自定义日期格式
```

---

## 解决方案对比

### 方案1：在云函数端统一格式（当前方案）✅ 推荐
**优点**：
- ✅ 不依赖客户端序列化库
- ✅ 统一格式，所有客户端都能解析
- ✅ 符合 JSON 标准（ISO 8601）
- ✅ 数据库仍保持 Date 类型（支持查询）

**缺点**：
- ⚠️ 需要在云函数中转换

### 方案2：配置客户端序列化库
**优点**：
- ✅ 客户端更灵活
- ✅ 可以处理多种日期格式

**缺点**：
- ❌ 依赖特定序列化库
- ❌ 如果切换序列化库需要重新配置
- ❌ 无法解决云函数返回格式不一致的问题

### 方案3：使用其他序列化库
**Unity JsonUtility**：
- ❌ 功能有限，不支持复杂配置
- ❌ 只支持 ISO 8601

**System.Text.Json**：
- ✅ 性能更好
- ✅ 但需要 .NET Core 3.0+
- ⚠️ Unity 可能不支持

---

## 推荐方案

**保持当前方案（云函数端统一格式）**，原因：

1. **标准化**：ISO 8601 是 JSON 中日期时间的标准格式
2. **兼容性**：所有序列化库都支持 ISO 8601
3. **独立性**：不依赖客户端序列化库配置
4. **可维护性**：格式统一，易于调试

## 如果要在客户端配置（可选）

如果需要更灵活的日期处理，可以配置 Newtonsoft.Json：

```csharp
public class CustomJsonHelper : Utility.Json.IJsonHelper
{
    private static readonly JsonSerializerSettings Settings = new JsonSerializerSettings
    {
        DateFormatString = "yyyy-MM-ddTHH:mm:ss.fffZ",
        DateTimeZoneHandling = DateTimeZoneHandling.Utc,
        // 或使用转换器
        Converters = { new IsoDateTimeConverter { DateTimeFormat = "yyyy-MM-ddTHH:mm:ss.fffZ" } }
    };

    public string ToJson(object obj)
    {
        return JsonConvert.SerializeObject(obj, Settings);
    }

    public T ToObject<T>(string json)
    {
        return JsonConvert.DeserializeObject<T>(json, Settings);
    }
}
```

但**不推荐**，因为：
- 云函数返回格式仍可能不一致
- 增加代码复杂度
- 不如在源头（云函数）统一格式
