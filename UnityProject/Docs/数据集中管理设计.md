## 一、设计理念

将所有游戏数据集中到 `SlimeGameData` 类中，由 `World` 统一管理和访问。采用**单一数据源**原则，避免数据分散在多个Manager中。

## 二、架构设计

```
World (统一管理器)
    └── GameData: SlimeGameData (所有游戏数据)
        ├── 用户数据 (UserInfo)
        ├── 货币数据 (Coin等)
        ├── 进度数据 (ProgressLevelID, GuideFinish)
        ├── 设置数据 (EnableSound, EnableVibration)
        └── 每日数据 (DailyChest等)
```

## 四、数据管理职责划分

### 4.1 SlimeGameData 职责

- **数据存储**：定义所有游戏数据字段
- **本地持久化**：使用 PlayerPrefs 保存/加载数据
- **数据变更通知**：数据变化时触发事件

### 4.2 World 职责

- **数据初始化**：从服务器加载数据并更新到 GameData
- **数据同步**：与服务器同步数据
- **业务逻辑**：通过 GameData 访问数据，执行业务操作

### 4.3 Manager 职责（保留）

- **业务逻辑**：提供业务方法（如 AddCoin、DeductCoin）
- **服务器交互**：处理网络请求和响应
- **内部调用**：内部使用 `World.Instance.GameData` 访问数据

```csharp

// 2. 成功后更新 World.Instance.GameData.Coin
// 3. 触发事件通知UI
```

### 5.3 数据同步

```csharp
// World 中统一处理服务器数据同步
public async void FetchUserGameInfo()
{
    var response = await NetManager.CallHttp<UserGameInfoData>("getUserGameInfoV2");
    if (response.IsSuccess && response.data != null)

        // 统一更新到 GameData

    }
}
```

## 六、实现要点

### 6.1 数据属性设计

**原则**：重要数据通过方法更新，设置类数据可直接设置

```csharp
// 重要数据（货币、进度）- 通过方法更新
public void UpdateCoin(int coin) { ... }
public void SetProgressLevelID(int levelID) { ... }

// 设置数据 - 直接属性设置（自动保存）
public bool EnableSound 
{ 
    get => _enableSound;
    set 
    {
        _enableSound = value;
        SaveLocal();  // 自动保存
    }
}
```

### 6.2 本地存储

- 使用 PlayerPrefs 存储
- 每个数据字段有独立的 Key
- 统一的前缀命名：`slime_xxx`
- 数据变化时自动保存（或批量保存）

### 6.3 事件通知

数据变化时触发事件，UI层监听更新：

```csharp
// Coin 变化时
GameEvent.Send(SlimeEvent.OnCoinChanged, coin);

// 用户信息变化时
GameEvent.Send(SlimeEvent.OnUserInfoUpdate, userInfo);
```

### 6.4 服务器同步

```csharp
// SlimeGameData 提供同步方法
public void SyncFromServer(UserGameInfoData serverData)
{
    if (serverData == null) return;
    
    // 同步各个字段
    UpdateCoin(serverData.coin);
    SetProgressLevelID(serverData.progressLevelID);
    UpdateUserInfo(serverData.nickName, serverData.avatarUrl, serverData.openID);
}
```

## 八、优势对比

### 8.1 当前方式

```
CurrencyManager (Coin)
SlimeGameData (UserInfo, Progress等)
DailyChestManager (每日数据)
```

**问题**：
- 数据分散，需要访问多个类
- 数据同步逻辑分散
- 难以统一管理

### 8.2 集中管理方式

```
World.GameData (所有数据)
    ├── Coin
    ├── UserInfo
    ├── ProgressLevelID
    └── ...
```

**优势**：
- ✅ 单一数据源，统一访问入口
- ✅ 数据集中，易于管理
- ✅ 同步逻辑统一
- ✅ 与现有架构兼容（World已存在）

## 九、注意事项

1. **数据访问**：统一通过 `World.Instance.GameData` 访问
2. **数据更新**：重要数据通过方法更新，确保保存和事件通知
3. **线程安全**：假设主线程调用，多线程需加锁
4. **向后兼容**：Manager 保留，内部使用 GameData，外部接口不变
5. **性能考虑**：频繁更新可考虑批量保存或延迟保存

## 十、实施步骤

1. **扩展 SlimeGameData**：添加 Coin 等字段和方法
2. **修改 CurrencyManager**：内部使用 GameData，外部接口不变
3. **统一同步逻辑**：在 World 中统一处理服务器数据同步
4. **测试验证**：确保数据存储、同步、事件通知正常
5. **逐步迁移**：其他数据逐步集中到 GameData

---

**总结**：将所有游戏数据集中到 `SlimeGameData`，由 `World` 统一管理，既解决了数据分散的问题，又保持了架构的简洁性。
