# 微信云开发数据库日期格式分析

## 一、微信云数据库的日期存储格式

### 1. 数据库内部存储
- **类型**：MongoDB Date 类型（基于 BSON）
- **存储格式**：UTC 时间戳（毫秒）
- **JavaScript 中**：`new Date()` 对象会被自动识别为 Date 类型

### 2. 存入数据库
```javascript
const now = new Date()  // JavaScript Date 对象
await db.collection('test').add({
  data: {
    createdAt: now,  // 直接存储 Date 对象
    updatedAt: now
  }
})
```
- ✅ **可以正常存入**：微信云数据库 SDK 会自动处理 Date 对象
- ✅ **支持筛选**：可以使用日期范围查询

---

## 二、从数据库读取后的格式

### 1. 在云函数中读取
```javascript
const result = await db.collection('test').get()
const data = result.data[0]

console.log(typeof data.createdAt)  // "object" (Date 对象)
console.log(data.createdAt)          // Date 对象，如: 2025-05-06T13:18:42.514Z
```

### 2. 直接返回给客户端（问题所在）
```javascript
// ❌ 问题代码
return {
  code: 0,
  data: result.data[0]  // 包含 Date 对象
}
```

**序列化过程**：
1. 云函数返回时，JavaScript 会调用 `JSON.stringify()`
2. `JSON.stringify(new Date())` 会序列化为 ISO 8601 字符串
3. **但**：微信云数据库返回的 Date 对象可能已经是特殊格式
4. 序列化后可能是：`"2025-05-06T13:18:42.514Z"` 或时间戳格式

---

## 三、传给 Unity 的序列化格式

### 场景1：直接返回 Date 对象（不推荐）
```javascript
// 云函数
const userData = await db.collection('test').get()
return { code: 0, data: userData.data[0] }
```

**序列化结果**（不确定）：
```json
{
  "code": 0,
  "data": {
    "createdAt": "2025-05-06T13:18:42.514Z",  // 可能是 ISO 字符串
    // 或
    "createdAt": 1715005122514,  // 可能是时间戳（毫秒）
    // 或
    "createdAt": { "$date": 1715005122514 }  // 可能是 MongoDB 格式
  }
}
```

**Unity 端解析**：
- ❌ **可能失败**：格式不确定，Newtonsoft.Json 可能无法解析
- ❌ **错误示例**：`Unexpected character encountered while parsing value: 1`

### 场景2：手动转换为 ISO 字符串（推荐）✅
```javascript
// 云函数
const userData = await db.collection('test').get()
const formatted = {
  ...userData.data[0],
  createdAt: new Date(userData.data[0].createdAt).toISOString(),
  updatedAt: new Date(userData.data[0].updatedAt).toISOString()
}
return { code: 0, data: formatted }
```

**序列化结果**（确定）：
```json
{
  "code": 0,
  "data": {
    "createdAt": "2025-05-06T13:18:42.514Z",  // 标准 ISO 8601
    "updatedAt": "2025-05-06T13:18:42.514Z"
  }
}
```

**Unity 端解析**：
- ✅ **成功**：Newtonsoft.Json 默认支持 ISO 8601 格式
- ✅ **格式统一**：所有客户端都能正确解析

## 五、最佳实践

### ✅ 推荐方案：统一转换为 ISO 字符串
```javascript
// 读取后立即转换
const userData = await db.collection('test').get()
const formatted = {
  ...userData.data[0],
  createdAt: new Date(userData.data[0].createdAt).toISOString(),
  updatedAt: new Date(userData.data[0].updatedAt).toISOString()
}
return { code: 0, data: formatted }
```

**优点**：
1. ✅ 格式确定：始终是 ISO 8601
2. ✅ 兼容性好：所有序列化库都支持
3. ✅ 易于调试：格式统一
4. ✅ 数据库仍保持 Date 类型（支持查询）

### ❌ 不推荐：直接返回 Date 对象
```javascript
// 问题：格式不确定
return { code: 0, data: userData.data[0] }
```

**缺点**：
1. ❌ 格式不确定：可能序列化为时间戳或其他格式
2. ❌ 客户端解析可能失败
3. ❌ 不同环境可能表现不同

---

## 六、总结

| 阶段 | 格式 | 说明 |
|------|------|------|
| **存入数据库** | `new Date()` 对象 | ✅ 微信云数据库自动处理 |
| **从数据库读取** | Date 对象 | ✅ 在 JS 中是 Date 类型 |
| **直接序列化返回** | ❌ 不确定 | 可能是 ISO 字符串、时间戳或 MongoDB 格式 |
| **手动转换后返回** | ✅ ISO 8601 字符串 | `"2025-05-06T13:18:42.514Z"` |
| **Unity 解析** | ✅ ISO 8601 字符串 | Newtonsoft.Json 默认支持 |

**结论**：当前方案（手动转换为 ISO 字符串）是正确的，确保了格式的统一性和兼容性。
